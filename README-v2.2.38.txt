====================================================
redcode-shop v2.2.38 —— 直播縮圖永久保存修復
====================================================

【今次解決咩】
你尋日問：「點解直播回顧啲 facebook 縮圖唔見晒？直播中嗰張會唔會都無？」

答案：會，兩邊係同一條路。原因係——
縮圖摷返嚟之後，之前淨係放喺 server 記憶體（RAM）。
每次 deploy 或者 Render 重開，記憶體就清晒，要即場問 FB 拎返。
但 FB 而家封緊我哋 server 嘅 IP（五條摷圖路線全部擋，呢場仗打過好多次），
拎唔返 → 全部跌落去我哋設計嘅 poster。
之前一直有，係因為舊 cache 一直留住未清過；尋晚 v2.2.37 個 deploy 清咗先爆。
（唔係新功能整壞：v2.2.36/37 完全冇掂過縮圖 code，純粹撞啱時間。）

【v2.2.38 點修】
而家縮圖有三層保存：
  1) server 記憶體（快取，同以前一樣）
  2) Render Persistent Disk（/app/uploads/live-thumb/）← 新加！deploy/重開都唔會冧
  3) 先至去 FB 摷
即係話：只要成功摷到一次，張圖就永久留喺你 10GB 隨身碟度，
以後點 deploy、點重開、FB 點發爛，縮圖都照出。
直播中嗰張同回顧嗰啲一齊受保護，唔使再「一覺醒來縮圖無晒」。

【今次郁咗邊啲檔】
  api/boot.ts （一個檔，加咗 disk 保存層，其餘邏輯冇變）
其他檔一個字都冇郁過。冇 DB 改動，冇新環境變數。

【部署方法（同平時一樣，你自己 push）】
  1. 解壓，將 api/boot.ts 冚過 repo 入面嗰個
  2. git add / commit / push 去 master
  3. Render 會自己 build 同 deploy，兩三分鐘搞掂

【部署後點驗收】
  1. 去官網「直播回顧」睇：
     - 如果 FB 仲封緊，縮圖會繼續係 poster——正常，唔係修復冇效
     - FB 一解封（通常幾個鐘到一兩日），任何人開個頁，縮圖即刻出返
  2. 出返之後，試多一次 deploy（或者等 Render 自己重開）：
     縮圖仲在 = 修復成功，以後都唔會再無
  3. 想即時靚仔唔使等 FB：官網後台每場直播「手動上傳縮圖」
     （v2.2.23 已有嘅功能），手動上傳嗰啲本來就永久保存，即刻見效

【補充】
  - 直播中條片本身一直冇受影響：片係客人部機直連 FB 播嘅，
    封 IP 只影響我哋 server 摷「縮圖」，唔影響客人睇片。
  - disk 保存嗰啲檔好細（每張幾十到幾百 KB），200 場都佔唔到 10GB 嘅零頭。
