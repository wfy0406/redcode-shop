一、抽中唔即時通知（你指令：撳咗「好，繼續」先正式發送）
----------------------------------------------------------------
舊制：輪盤一停，email＋推播即刻飛出去。
新制：抽中嗰刻淨係落咗中獎紀錄，乜都唔發。管理員/主管睇清楚個結果，
撳「✓ 好，繼續」（會員池）或「✓ 冇問題，抽下一件」嗰刻，先至正式
寄中獎 email＋推送，等客人入官網揀地址確認。

安全網（唔會出事故）：
・ 原子認領——兩個人一齊撳、或者撳完再撳，都只會發一次，
  第二次會話你知「通知之前已經發咗，唔會重複發」。
・ 發送失敗唔會收卡——錯誤會彈出嚟，可以即刻再撳。
・ 紀錄頁（抽獎紀錄嗰版）：未通知嘅 pending 中獎會有金色
  「未通知」badge＋「📣 發通知」補發掣——抽完閂咗頁都補得返。
・ 手打名中獎（影子帳號）唔受影響——佢哋本來就冇 email/推送，
  照舊行「✓ 確定中獎（出 0 元單去 WMS）」路線，制式冇變。
・ 如果客人未收到通知已經自己入官網確認咗，撳發通知會提你
  「客人已經喺官網確認咗寄送，唔使再發通知」。
・ 舊中獎紀錄：migration 第一次加欄嗰刻會自動標晒做「已通知」
  （舊系統本來就抽中即發），之後新抽嘅唔會被誤標。

二、指定抽（你指令：客人嗌「抽 3 號先」可以即抽嗰件）
----------------------------------------------------------------
輪盤上面多咗個模式切換：
・ 「順序抽（自動下一件）」——預設，同依家一模一樣，抽完自動跳下一件。
・ 「指定抽（撥號碼）」——每件獎品有金色號碼 badge（1 號、2 號…），
  號碼同下面「獎品管理」卡片嘅編號一致，直播客人嗌「3 號」，
  你撥 3 號 chip 就抽 3 號。同款有幾件可以停喺嗰度連抽。
・ 指定嗰件抽晒之後，唔會靜靜雞跳返第一件（直播抽錯獎品係事故）——
  會停低＋提示你撥返另一個號碼。
・ 轉模式／揀獎品喺抽緊嗰陣會鎖住，唔會半路俾人搞亂。
・ 「每人一日最多中一件（除非冇人又排到佢）」嘅規則完全冇郁，
  server 嗰邊照舊把關。

三、iPhone 中獎公仔黑盒（你實測 Instagram 內開變黑背景）
----------------------------------------------------------------
成因：iPhone 上所有瀏覽器（Safari、Chrome、Instagram in-app 全部
都係 WKWebView）永遠解唔到 VP9 透明影片——舊碼靠播緊嗰刻探測，
但 WKWebView 探測有時機誤判，就會當不透明咁播 → 黑盒。
修法：WebKit 系（iPhone/iPad 所有瀏覽器＋macOS Safari）唔再試 WebM，
開局直出真透明動畫 WebP（乜 WebKit 都透）；其餘瀏覽器照播 WebM，
探測加咗雙保險（空白幀唔算數＋500ms 再探一次），黑盒無可能留低。
另外補咗個漏：reduced-motion 嘅 iPhone 用戶同慢網下載緊嗰陣，
會繼續顯示靜態 poster，唔會成隻公仔唔見咗。
（Android／電腦 Chrome 行為不變；靜圖、動畫 WebP、WebM 三層都係真透底。）
