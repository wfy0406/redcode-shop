二、最重要：而家只係同事／管理員內測

未做真人＋真商品品質驗收前：
1. memberEnabled 必須保持 false。
2. qualityApproved 必須保持 false。
3. 唔好宣稱已正式開放會員，亦唔好將 QA mock 圖當真生成效果。

生成係提交後異步工作，唔係即時布料 AR；畫面只顯示真實 queued／processing／completed／failed 狀態，唔顯示假百分比。
固定 adapter 係 tryon-max、generation_mode=quality、resolution=1k、一張 PNG；供應商計費係每次生成 3 credits。混搭每件都係另一次生成、另一次額度及成本預留，每套最多 3 件，每次都要用戶確認，唔會自動連續收費。

AI 試穿只係視覺預覽，唔代表實際尺碼、鬆緊、合身程度或舒適度；尺寸以商品尺寸表及實物為準。商品原圖係唯一衣服依據，但生成式 AI 仍可能改錯細節，所以真人驗收係開放前必要條件。

四、部署步驟（由你執行）

1. 先備份而家 repo，並按你平常流程備份資料庫。建議先 commit 手上乾淨版本，方便對照及 rollback。
2. 解壓本 ZIP，將內容冚過官網 Website repo 根目錄。只係覆蓋同名檔及加入新檔；唔需要刪除其他現有檔案。
3. 喺解壓後嘅 repo 根目錄，可用 Linux／macOS／Git Bash 執行：
   sha256sum -c SHA256SUMS
   全部顯示 OK 先代表逐檔同交付版本一致。呢步只係完整性檢查，唔係連資料庫嘅驗證。
4. 喺 Render／你嘅秘密管理設定以下項目；唔好將真值寫入 repo 或回本畀任何人：
   - FASHN_API_KEY：由供應商取得，只放 server-only 環境變數；唔好加 VITE_ 前綴。
   - APP_SECRET：沿用現有強隨機秘密；私人媒體 signed URL 會用到，唔可以空白。今輪冇亦唔會替你 rotate。
   - PUBLIC_BASE_URL：正式站用 https://redcode.red。
   - UPLOADS_DIR：沿用現有 persistent disk／上傳設定。
   - TRYON_PRIVATE_DIR：可選；如覆寫，必須係私人持久目錄，唔可以被公開靜態路由直接讀取。
5. 今輪冇新 npm dependency，package.json／lockfile 均不變。按你正常流程 commit、push；Render 會按現有設定 auto-deploy。我冇替你 push、merge 或部署。
6. 開機後現有 ensureDatabase() 會自動執行 CREATE TABLE IF NOT EXISTS，建立 tryOnJobs 同 indexes；成功後先啟動試穿媒體清理及卡住工作恢復。請睇 Render logs 確認冇 [boot-migrate] failed；唔需要亦唔好跑會連 production DB 嘅 check-db／fix-db／verify 腳本。
7. 到 Admin「AI 試穿」檢查 provider 狀態，設定員工／全站上限、每 credit 成本及每月預算。會員開放前，成本單價、每月預算、最低級別及各級每日額度都要明確設定。
8. 保持會員開關及品質批准關閉，先用同事／管理員帳號做第五節驗收。

五、真人＋真商品驗收清單

每次真生成都可能產生供應商費用；混搭每件獨立計費。請用小額、可追蹤嘅內測額度。

1. 用真 DB 商品詳情頁入 /try-on，換商品相片後確認帶入嘅係你而家睇嗰張。
2. 分別試後鏡、前後鏡切換、相簿 JPEG／PNG／WebP；拒絕權限後試重新檢查及相簿 fallback。HEIC／HEIF 應按 FAQ 先轉 JPEG。
3. 觀察 queued／processing／completed／failed，確認冇假百分比、冇自動追加下一件。
4. 逐件對照真人同商品：樣貌、五官、髮色、身形、姿勢唔應為遷就衣服而改；商品款色、印花、細節及材質觀感唔應憑空改變。「著得靚」只接受自然貼合、合理垂墜、褶皺、比例及冇穿模，唔係美顏或改身形。
5. 上衣＋褲、上衣＋戒指等不同部位各試一次；相同部位應被拒。飾品要逐類驗證位置；server placement prompt 只係降低風險，唔係品質保證。
6. 完成後下載 PNG，檢查可正常開啟。手機支援時試 Web Share files＋text；WhatsApp fallback 應有每件品名、貨號、生成時價錢及公開商品網址。私人結果圖要先下載再自行附加到 WhatsApp。
7. 試失敗重試、刪除第二步再追加、刪除根步、重新整理恢復，以及已刪工作唔再永久報錯。
8. 核對 Admin 日／月／年統計：成功、失敗、處理中、預留點數、已用點數、估算成本及成本待核實應分開；再同供應商實際 credits／帳單對數。
9. 檢查私人原相及結果唔能透過公開 /uploads/:file 讀取；owner 以外帳號唔能讀；signed URL 到期後可由頁面有限刷新；即時刪除及 24 小時清理要實測。
10. 用真 iPhone／Android、桌面、平板及 App WebView 各跑一次。真機相機權限、原生分享及 WebView 行為唔係桌面 Chromium mock 可以代替。
11. 只有品質、私隱、額度、成本及每月預算全部通過後，先由你決定是否開品質批准，再開會員或指定最低級別。
